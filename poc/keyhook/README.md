# keyhook — Phase 0 PoC

`WH_KEYBOARD_LL` 저수준 키보드 훅이 **실제로 쓸 만한지** 확정하기 위한 순수 Rust 검증 도구.
Tauri와 결합하기 전 단계이며, 여기서 확정하려는 건 코드가 아니라 **동작**이다.

프로젝트 전체 리스크 1순위가 이 훅이다 — 여기서 막히면 나머지 계획이 전부 무의미해진다.
자세한 배경은 [docs/PLAN.md](../../docs/PLAN.md) §14(로드맵) · §15(리스크) 참고.

## 실행

```bash
cargo run --release
```

> `--release` 없이 돌리지 말 것. 콜백 지연 측정이 디버그 빌드에서는 의미가 없다.

종료는 `Ctrl+C`, 카운터 리셋은 `F12`.

## 검증 항목

### 1. 카운팅 규칙 (PLAN.md §4)

`F12`로 리셋한 뒤 하나씩 확인한다.

| 입력 | 기대 총 카운트 | 확인하는 것 |
|---|---|---|
| `asdf` | **4** | 기본 |
| `Shift+A` | **2** | modifier도 물리 입력이므로 센다 |
| 한글 `한` (ㅎ+ㅏ+ㄴ) | **3** | IME 조합 중 자모도 물리 키 다운 |
| 아무 키나 3초 꾹 누르기 | **1** | auto-repeat은 `auto-repeat 드롭`으로만 올라가야 함 |
| Backspace · 방향키 · F키 · Enter | 각 **1** | "순수 입력량" 모델 — 전부 포함 |

### 2. 관리자 권한 (UIPI)

비-elevated 프로세스는 관리자 권한 앱의 입력을 받지 못한다. 이게 사실인지 실측한다.

1. **일반 권한**으로 실행 → 화면 상단에 `일반 사용자`로 표시되는지 확인
2. 그 상태로 관리자 권한 앱(예: 관리자 PowerShell)에 포커스를 주고 타이핑
   → **카운트가 안 오르면** UIPI 제약이 실재하는 것
3. **관리자 권한**으로 실행(관리자 PowerShell에서 `cargo run --release`)하고 2를 반복
   → 이번엔 올라가야 한다

이 결과에 따라 PLAN.md §11의 자동 시작 방식(작업 스케줄러 vs Run 레지스트리)이 갈린다.

### 3. 안티치트 호환성

주요 게임을 **borderless windowed**로 켜 놓고 게임 안에서 타이핑한다.

- Vanguard 계열(발로란트·LoL), EAC 계열
- 카운트가 오르는지, 게임이 튕기지 않는지, 입력이 밀리지 않는지

**곁다리로 오버레이 스파이크도 여기서 함께 확인한다** (PLAN.md §8) — 게임을 어차피 켜야 하므로.

### 4. 입력 지연

`콜백 최대` 값을 본다. **OS 임계는 300ms**이고, 이를 넘기면 Windows가 훅을 조용히 제거하면서
시스템 전체 입력이 밀린다. 이 설계(콜백은 채널 push만)에서는 마이크로초 단위여야 정상이다.

`이벤트 유실`이 0이 아니면 설계가 틀린 것이다.

### 5. 8시간 무누수

켜 두고 하루 일과를 보낸 뒤 확인한다.

- `메모리 RSS`가 초기값에서 자라지 않았는가
- `콜백 호출`이 계속 증가하는가 → 멈췄다면 **훅이 조용히 죽은 것**
- `워치독 보정`이 비정상적으로 크지 않은가

중간에 **Win+L 잠금**, **UAC 승격**, **원격 데스크톱 전환**을 한 번씩 끼워 넣는다.
`현재 눌림`에 아무것도 안 눌렀는데 키가 남아 있으면 keyup 유실이 재현된 것이고,
워치독이 1초 안에 이를 회수해야 한다.

## 화면 읽는 법

| 항목 | 의미 |
|---|---|
| `총 카운트` | 검증 대상. auto-repeat·injected를 제외한 물리 키 다운 횟수 |
| `auto-repeat` | 꾹 누르기로 드롭된 이벤트 수 |
| `injected` | `SendInput` 합성 입력(AHK 매크로 등). 카운트에서 제외하고 따로 센다 |
| `워치독 보정` | keyup을 놓쳐 "눌림"으로 남았던 키를 회수한 횟수 |
| `콜백 최대` | 훅 콜백 1회 최대 소요 시간. 300ms 임계 대비 여유 확인 |
| `이벤트 유실` | 채널이 막혀 버려진 이벤트. **항상 0이어야 한다** |
| `현재 눌림` | 지금 눌려 있다고 판단 중인 키. 손을 뗐는데 남아 있으면 keyup 유실 |

## 이 PoC가 하지 않는 것

- 저장하지 않는다. 프로세스가 죽으면 카운트도 사라진다.
- 서버로 아무것도 보내지 않는다.
- 키 **순서·내용을 기록하지 않는다.** 키별 누적 횟수만 메모리에 둔다 (PLAN.md §10 프라이버시 철칙).
