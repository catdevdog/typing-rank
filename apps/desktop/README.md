# TypingRank 데스크탑 클라이언트

Windows 상주 앱. **계정 없이 완결된다** — 설치하면 바로 카운트가 시작되고,
대시보드·트레이·오버레이가 전부 로컬로 동작한다. 랭킹 참여는 선택이며,
참여하기 전에는 타이핑 데이터가 서버로 나가지 않는다.

기획: [docs/PLAN.md](../../docs/PLAN.md) — §4(카운팅 규칙) · §7(진입 흐름) · §10(프라이버시) · §14(로드맵)

## 실행

```powershell
cd src-tauri
cargo run --release
```

> **관리자 권한이 필요하다.** UIPI 때문에 비-elevated 훅은 관리자 권한 앱의 입력을
> 받지 못한다 — Phase 0에서 실측 확정됐다(§11). 일반 권한으로 띄우면 대부분 동작하지만
> 관리자 터미널 등에서 친 키가 조용히 누락된다.

첫 빌드는 rusqlite `bundled`(SQLite C 소스 동봉) 때문에 몇 분 걸린다.

## 구성

```
src-tauri/src/
├─ main.rs      Tauri 조립. 스레드 3개를 잇기만 한다
├─ hook.rs      WH_KEYBOARD_LL. 콜백은 채널 push만, 판정 없음
├─ counter.rs   카운팅 규칙(§4) + 워치독 + 주기적 flush
└─ store.rs     로컬 SQLite. 집계만 기록, 시퀀스 없음
```

**스레드 3개는 서로를 기다리지 않는다.** 훅 콜백이 `LowLevelHooksTimeout`(기본 300ms)을
넘기면 OS가 훅을 조용히 제거하고 시스템 전체 입력이 밀린다. Phase 0 실측 최대 79µs.

### 저장 위치

`%APPDATA%\TypingRank\typingrank.db`

§12가 런타임 설정 파일을 `%APPDATA%\TypingRank\config.json`으로 지정했으므로 같은
디렉터리를 쓴다. Tauri의 `app_data_dir()`은 번들 식별자를 그대로 폴더명으로 써서
(`%APPDATA%\dev.typingrank.app`) 기획과 어긋나므로 쓰지 않는다.

**집계만 저장한다.** 키가 눌린 순서·시각은 남기지 않으며, 저장된 것으로 입력 내용을
재구성하는 것이 구조적으로 불가능하다. 스키마에 시퀀스 컬럼을 추가하려는 순간
이 철칙이 깨지는 것이므로 다시 생각할 것.

## Phase 0에서 가져온 수정 2개

| 항목 | 내용 |
|---|---|
| **워치독 `last_down_at`** | PoC는 눌린 키를 매초 무조건 `GetAsyncKeyState`로 되물어, 채널에 대기 중인 keyup을 앞질러 보고 유실로 오판했다(203 카운트에 16회). **1초 이상 눌린 키만** 검사하고, 워치독 전에 채널을 먼저 비운다 |
| **훅 사망 대응** | 훅이 죽었는지 알 수 있는 API가 없다. 5분마다 떼었다 다시 건다. 재설치 비용은 마이크로초 단위고, 훅이 죽은 채 도는 것은 카운트가 0인 것과 같다 |

## 일시정지는 "무시"가 아니라 "언훅"이다

비밀번호를 칠 때 끌 수 있어야 앱을 깔 마음이 든다(§10). 그렇다면 플래그로 무시하는 게
아니라 **훅 자체를 떼어야** 한다. 오픈소스라 유저가 이 차이를 직접 확인할 수 있고,
그게 이 프로젝트의 신뢰 장치다.

## 프론트엔드

지금은 정적 HTML 한 장(`ui/index.html`)이다. React 대시보드를 붙일 때
`tauri.conf.json`의 `frontendDist`를 `../ui` → `../dist`로 바꾸고 Vite를 연결한다.
**Rust 코어는 Node 없이 빌드·실행된다.**

- 업로드 관련 일체 (Stage 3)
